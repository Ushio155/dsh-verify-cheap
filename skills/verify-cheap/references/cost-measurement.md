# 耗时测量与成本记录（cost-measurement）

配合 `SKILL.md` 第五节使用。文中路径均相对本技能目录（`skills/verify-cheap/`）。

## 一、两个必须区分的数字

| 数字 | 含义 | 来源 |
|---|---|---|
| 外部总时长 | 从进程启动到退出的墙上时间，即用户感知的成本 | 计时外壳或 `scripts/measure-runtime.mjs -- <命令>` |
| 脚本内计时 | 脚本自己统计的分段耗时之和，即工作真正花掉的时间 | `createTimer()` 的分段记录 |

两者持续不一致，说明有东西挂在事件循环上：未关闭的句柄、连接或定时器。典型原因是成功路径未调用 `process.exit()`。

## 二、分段耗时表格式

按 `[小节]` 边界分段，输出三列：小节 / 耗时 / 占比，随后输出合计与内外对比：

```
[verify-cheap] 分段耗时 — L2 注入回归
| 小节 | 耗时 | 占比 |
|---|---|---|
| prepare | 1.20 s | 40.1% |
| run | 1.79 s | 59.9% |
内部合计: 2.99 s
外部总时长: 8.42 s
差值: 5.43 s (阈值 2.00 s)
提示: 外部耗时明显大于内部计时，检查未释放的句柄/连接/定时器，或在成功路径补 process.exit()
```

## 三、内外部差异判定

工具只算**一个阈值**，取两者中的较大者：

```
阈值 = max(GAP_ABSOLUTE_MS, 内部计时 × GAP_RATIO)      // 默认 max(2 s, 30%)
```

> ⚠️ 是 **max（取较大者）**，不是"低于 2 s **且**低于 30%" —— 内部计时 10 s 时阈值是 3 s，不是 0.6 s。

判定只有**两档**，对应脚本打印的两句话：

| 差值 | 输出 | 处理 |
|---|---|---|
| ≤ 阈值 | `判定: 内外耗时一致，无事件循环挂起迹象` | 无需处理 |
| > 阈值 | `提示: 外部耗时明显大于内部计时…补 process.exit()` | 检查未关闭的句柄 / 连接 / 定时器 |

差值**比内部计时本身还大**时基本可以断定进程没退出 —— 但工具不会单独标出这一档，那是人的判断，别写成"工具的第三档"。

两个常量在 `scripts/measure-runtime.mjs` 顶部（`GAP_ABSOLUTE_MS` / `GAP_RATIO`），可按项目调整。

## 四、工具用法

```
# CLI：测量任意命令的外部总时长，子进程 stdio 直接继承
node scripts/measure-runtime.mjs --label "L3 全量" -- npm test
node scripts/measure-runtime.mjs --json -- pwsh -File build.ps1
```

```js
// 库：在脚本内分段计时，跑完打印分段表与内外对比
import { createTimer } from "./scripts/measure-runtime.mjs";   // 路径相对本技能目录
const timer = createTimer("L2 注入回归");
await timer.section("prepare", async () => { /* ... */ });
await timer.section("run", async () => { /* ... */ });
timer.report({ exit: 0 });     // 省略 exit 则不退出进程
```

## 五、成本记录

每次验证结束记录三项：档位（L0–L3）、实测耗时、能否再降一档。成本表落在**仓库根 `.verify-cost.md`**，这是默认约定，目的是让"实测耗时"有固定出处而不是每次现编；仓库已有 `SUMMARY.md` 这类长期索引时，并进其中「成本表」小节即可，别再开第二份。汇报耗时直接引用这张表：

| 命令 / 脚本 | 档位 | 实测耗时 | 前置条件 | 能否再降一档 |
|---|---|---|---|---|
| `<命令>` | L0 | 0.4 s | 无 | 已是最低档 |
| `<命令>` | L2 | 42 s | 需要构建产物 | 可拆出单套件降到 L1 |

汇报格式：`结论 + 档位 + 实测耗时 + 出处（脚本与分段）`。禁止使用"大概 / 感觉 / 印象里"。
